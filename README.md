## 直接启动

双击项目根目录 **`启动翻译姬.cmd`**，打开 `dist/0.5.1-voice/FanyiJiVoiceNext/FanyiJiVoiceNext.exe`，显式使用项目的 `settings/voice.settings.json`，并提供本项目 `models` 目录作为默认模型位置。完整程序目录、`settings` 和 `models` 都应保留。

1. 点击顶部 **声音与模型**，检查两路方向和本地模型位置。麦克风默认中文 → 日文，电脑声音默认日文 → 中文；只需一路时可关闭另一路。
2. 可点击 **刷新设备列表** 后选择设备；也可以使用系统默认设备。电脑声音使用 WASAPI loopback，不需要虚拟声卡。
3. 点击 **应用设置** 保存。取消会丢弃本次对话框改动；应用不会开启录音或加载模型。
4. 点击 **开始翻译**。程序在后台加载本地模型，再开启所选声音来源；音量条表示输入能量，待处理段数表示积压。
5. 点击 **停止** 后等待资源释放。字幕保留，可复制、导出或清空；停止完成后才能修改设备、模型或再次开始。

在 **声音与模型 → 识别与翻译引擎** 分别选择后端。两个后端组合独立，切换时保留各自模型路径；只有选中的后端在手动开始时加载。SenseVoice 固定使用原有 CPU ONNX；Whisper 与 CTranslate2 翻译模型可选 CPU INT8 或 NVIDIA GPU 的 INT8／INT8+FP16／FP16；Hy-MT2 使用固定 Q8_0 GGUF 与 NVIDIA GPU，独立本地运行库不与 CTranslate2 精度混用，缺少 GPU 或运行库时报错，不自动回退。首次建议先验证单路，再开启双路；两路共享同一套模型及有界识别队列。

NLLB 权重许可为 **CC-BY-NC-4.0**，官方定位研究模型，不面向生产部署；它不因转为 CTranslate2 或本地运行而改变许可。准备商用时应重新选择许可合适的翻译模型或取得相应授权。[Meta 模型卡](https://huggingface.co/facebook/nllb-200-distilled-1.3B)

标准项目目录内直接运行 EXE 时，同样使用项目的 `settings/voice.settings.json` 和 `models`。移出项目目录的独立程序可将模型放到 EXE 同目录下的 `models`，或通过 **声音与模型** 选择。源码入口是 `python run.py`，也可传 `--model-root <本地模型目录>`。

## 界面与字幕

- 顶部显示当前识别与翻译模型、声音处理模式。鼠标停在该标签或“声音与模型”按钮可查看配置文件绝对路径，设置对话框也显示可选择复制的路径；不同窗口的版本号相同不代表所选引擎相同。
- M2M100／NLLB 解码后会检查明显退化输出。只有大量重复、无有效文字或损坏字符才最多重试一次，使用更宽 beam 与 3-gram 重复限制；正常输出沿用原参数，不删改原文或去重字幕。重试仍无效则显示失败提示并保留原文。Hy-MT2 的候选检查也覆盖同类退化，已有上文候选回退机制保留。检查通过不代表词义、语气、歌词残句或上下文翻译准确。
- `0.4.1` 语音主页面直接显示连续字幕流：每句原文和译文成对排列，新句追加到底部。原文与译文可选择、复制，最新一句不再单独占据主区域。
- 两路字幕并排、上下专注阅读或单路铺满；保留本窗口内全部语音字幕，不再按每路 100 条淘汰。停止后再开始保留记录，只有手动清空、切换到预置模拟演示或关闭窗口才结束这份临时记录。
- 新句到来时自动滚动到最新；上方字幕移出可视范围后仍保留，可用鼠标滚轮向上回看。回看时暂停跟随，迟到的译文和字号变化也不会打断阅读；点击 **返回最新**、顶部 **本次字幕** 或向下滚到底恢复跟随。
- 专注模式也使用相同的连续字幕流。不同采集轮次使用独立片段编号，避免重新开始覆盖旧句。导出只在手动选择路径后写入文本；不自动保存到磁盘。
- **阅读设置** 调整字号、原文显隐、置顶和动态效果。真实运行期间可调整阅读外观；**声音与模型** 仍可打开查看，修改、浏览和设备刷新需停止完成后解锁。对话框提供 **停止以修改**，等待资源释放后自动解锁；取消查看不会停止采集，停止不会清空字幕。
- 小窗口收起大标题，把主区域留给字幕流；设置对话框内部可滚动。
- 语音模式 `Space` 开始／停止，`Ctrl+E` 导出；聚焦输入框、复选框或按钮时保留其自身键盘操作。
- 运行中关闭窗口会等待当前原生任务及声音设备释放，再自动关闭；界面保持响应。

## 本地处理方式

**声音与模型 → 电脑声音增强** 可选择原声直通、GTCRN 流式降噪、MDX 人声提取或 MDX + GTCRN。GTCRN-only 将原生输入按通道均值转成单声道，只进行一次 HQ 流式重采样到 16kHz，再将有状态 GTCRN 输出与相同源样本区间的原声各混合 50%，进入 VAD → 识别 → 翻译。这里的 only 表示绕过 MDX，不等待其整窗。原声保护用于减轻弱人声抑制，按连续源样本配对，稳态缓存最多 511 个 16kHz 样本，异常长度或无效波形会明确报错；不按回调时间错位混合，也不补缺音。它仍会保留部分游戏声和音乐，不等于人声分离，也不能保证识别完整。raw、MDX、MDX + GTCRN 的声音处理保持原实现。

MDX 模式保留原生立体声，以 44.1kHz 输入 Kim_Vocal_2，再转为 16kHz 单声道进行可选 GTCRN 降噪，之后进入相同识别与翻译链；麦克风维持原有路径。未指定模式的旧配置及新安装默认原声直通，发现本地模型不会擅自开启增强；现有项目配置继续保留所选模式。

Kim_Vocal_2 是固定窗口批处理模型，首批需要约 **5.8 秒原声，另加 CPU 推理、断句和识别翻译时间**，不能保证即时字幕。GTCRN 在这里使用有状态的流式处理，已出音频按原始样本时间轴计时；计算暂停不会误判为原声静音。回调与分离计算使用独立线程，待处理输入上限约 12 秒，输入丢失或增强积压超限会明确停止，保留已显示字幕。停止时丢弃尚未处理的尾音，待当前原生调用退出后释放资源；切换模式需停止完成，不自动切回原声。

分离可能误伤轻声、语气词，也可能保留游戏角色配音；它不保证只保留主播，更不能保证翻译正确。可用相同原声对比三种模式的句尾、否定与实际延迟。两份增强模型放在 `models/audio-processing/`，来源及 SHA-256 见其中的 `model-sources.json`。[MDX 模型来源](https://github.com/TRvlvr/model_repo/releases/download/all_public_uvr_models/Kim_Vocal_2.onnx)；[GTCRN 官方流式示例](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.8/python-api-examples/online-speech-enhancement-gtcrn.py)。

麦克风和系统回放分别采集，经多声道转单声道、SoXR 流式重采样到 16kHz。发现本地 `vad/silero_vad.onnx` 时，两路分别使用独立 Silero VAD，以约 0.35 秒非语音作为结束条件，不再叠加旧的能量静音等待。电脑声音在检测语音前后保留最多 120／160 ms 的真实音频，降低轻声起头、句尾被裁掉的风险；不补造音频或越过六秒上限。延迟测量仍按检测到的语音边界计算。缺少 VAD 模型时提示并使用原有能量断句（麦克风、电脑声音各约 0.55 秒）；已有 VAD 文件但无法加载时会报错停止。两路仍保留约 6 秒的连续发言保护上限。

六秒强制切段后，适配层保留全局源时间轴、pending 和真实音频历史，重置 native Silero 检测器，并重放约 608ms 已收到的历史来保留短续尾检测。重放不增加源样本计数，不重复提交已交付区间；非零短尾不增加能量或时长过滤。该修正针对实录重放出现的 native 负长度缓冲错误，不代表句尾识别已全部正确，也不改变静音等待或六秒上限。

SenseVoice 或通过 faster-whisper 运行的 Whisper large-v3 返回原文，Hy-MT2 本地 GGUF 或 M2M100／NLLB 的 CTranslate2 后端做中日互译，结果按通道和片段编号回填字幕。Whisper 使用原语言转写，语言按通道翻译方向指定；不使用其转为英文的 translate 任务，也不重复开启内置 VAD。NLLB 使用配套 tokenizer 和 `zho_Hans`／`jpn_Jpan`，没有复用 M2M100 的语言标记。

Whisper 保持首轮 beam5、不沿用前段文字，在库判定低 logprob 或高压缩比时最多增加一次温度 0.2、best_of=1 的重解码；普通片段仍走首轮。记录不含正文的分段置信度诊断，缺失分数为未知；低分判定和重试不能保证专名、口语或识别结果正确，也不会按常见短语黑名单删除字幕。

VAD 区分语音与非语音，不识别说话人，也不是人声与游戏声音分离、降噪或回声消除。游戏人物对话、歌声和部分音效仍可能被判断为语音并触发六秒保护上限。外放中的人声仍可能被麦克风识别，建议使用耳机。更换大模型不会自动增加逐字流式字幕；仍在一句结束或达到约六秒上限后才进行识别。

两路设备由同一个后台线程持有唯一 `PyAudio` 实例，依次打开、启动和释放。两条音频处理线程只消费内存中的字节数据；设备枚举与采集互斥。设备列表尚在读取时需要等待完成后再开始；关闭窗口会异步等待设备读取或采集任务结束。

当前是断句后显示结果，不显示逐字识别草稿。原始音频仅在有界内存缓冲中处理，不保存录音；识别队列最多 6 段，满时跳过最新整段并提示，避免无限积压。停止会丢弃尚未提交或处理完成的片段；已经显示的原文保留，未完成的译文明确标记为“已停止翻译”。重新开始建立新的采集编号并保留逐句历史，迟到结果不会串入新一轮。

## 上文翻译与保护边界

Hy-MT2 按声道、翻译方向保留已经识别的前两句源文。`0.4.6` 日译中有上文时，将前两句与当前句作为连续的三个源文段落一起翻译，使用源文中未出现的分隔符校验段落数，只向界面返回最后一段。这样可利用相邻句的语境，避免模型将上文复述直接当成当前字幕；不把历史译文传回模型。段落缺失、多出、空段或生成未完成时，最多回退一次当前句独立翻译。无上文时直接翻译当前句。中译日保留先独立初译、再参考上文的双遍方式。原文在翻译前将可确定的汉字数值标准化，双方对照使用相同预处理。

上下文请求为两段／三段分别预留 560／816 个输出 token，并在同一 2048 token 窗口内相应缩小输入预算。超预算时移除完整的最早一句上文，不截断当前句；上文全部移除后独立翻译。通常仍参考前两句，极长的连续识别文本可能减少实际使用的上文。诊断记录实际段数、生成次数与 token 预算，不记录段落正文。

针对实测词义错误增加三类有限的语境术语提示：有 HP／体力条减少依据时的 `溶ける`（掉血）、直播余时和未完环节语境中的 `巻く`（加快进度）、筛网语境中的 `目／粗い`（网眼／偏大）。只依据实际保留的源文上文与当前句触发，不改写模型最终译文；当前出现冰、蜡、卷线、卷袖、人物眼睛等明确本义对象时不应用对应提示。没有足够依据时沿用普通请求，独立回退也不携带该提示。这是有限词义辅助，不是完整游戏词库或通用语义校验。

可检测的数值变化、明确禁止表达丢失，或已支持的明确愿望被改成同动作禁止时，回退同一 Q8 的当前句独立翻译；该结果仍未通过时保留原文并提示失败，不直接改写译文。日译中还检查较长的逐字上文译文复用，只将成功译文用于检查，不传回模型。对于含 `こっち／そっち` 等指示词且当前句没有明确时间的日语，仅检查新增的“上午／下午”等时段是否在实际使用的上文中有依据；不猜测指代对象，也不决定两个已知时段应选哪一个。意向和依据检查均为有限规则，不是通用语义校验。

数值检查不再把表示“从一开始”的 `最初から` 当成序号 1；真正的首次、第一回和原文中的金额、次数仍参与原有一致性检查。禁止语气检查排除推测尾语 `だろうな／でしょうな`，不再把 `そうだろうな` 误认为命令；`行くな／するな` 等真实禁止仍检查。

对全串为特定重复促音音拍或重复 `しー` 长音的片段，Hy-MT2 保留完整识别原文，并标记“音节含义待确认”，避免按上文猜成喜悦、称呼或其他动作。这不是通用噪声判断，不按短句、纯假名或重复本身过滤；正常的 `ナイス`、`やった`、`はいはい` 及跨段重复仍会显示。其他杂乱专名和含糊原文仍可能误译。

中译日通常有两次生成，日译中通常一次、保护回退时两次；完整译文耗时以实际测试为准。检查属于有限规则，不能保证所有否定、数字、词义或指代正确，不能完整验证双重否定、动作范围、数字所指对象及原句无数值时新增数字的依据。每次重新开始采集会新建上文，不同声道不混用。NLLB／M2M100 保持原来的当前句单译方式。

两句模型上文与主页面字幕历史分别保存在内存。字幕历史停止后仍可回看；关闭窗口前可手动导出，关闭重开不自动恢复，也不会后台保存真实字幕正文。

Hy-MT2 模型与运行库独立放置，选择模型文件不会改变 NLLB 的路径。Hy-MT2 官方模型卡标明 Apache-2.0；具体模型使用以随附文件和官方说明为准。[腾讯模型卡](https://huggingface.co/tencent/Hy-MT2-1.8B)。本机已校验的模型/runtime来源及评测记录在 artifacts/hymt2-context-r2。

## 源码环境与验证

本项目使用自己的 `.venv`，Python `3.12.13`。`requirements-lock.txt` 固定完整依赖版本，既有运行库版本保持不变；新增 faster-whisper 1.2.1、tokenizers 0.22.2 及配套依赖。模型转换环境独立使用 `requirements-models-lock.txt`，不随应用打包。GPU 额外依赖固定为 NVIDIA cuBLAS 12.4.5.8、cuDNN 9.10.2.21；后者与既有 CTranslate2 4.8.2 的 cuDNN 主库版本一致。

源码完整安装可使用 `.[voice,gpu,dev]`；精确重现请使用锁文件。GPU DLL 仅安装在新项目环境或便携目录中，运行时注册到当前进程的搜索路径；不修改系统驱动、注册表或全局 PATH。只有选 CUDA 时才配置这些 DLL，CPU 路径不依赖 NVIDIA 包。新建语音便携包需要准备 `voice` 和 `gpu` 依赖，构建脚本会检查完整 DLL 集合并保留许可证。

- 全量测试：`.venv/Scripts/python.exe -m pytest -q`
- 不采音界面检查：`.venv/Scripts/python.exe run.py --smoke-test --report artifacts/voice/ui.json`
- 依赖检查：`.venv/Scripts/python.exe run.py --check-runtime --report artifacts/voice/runtime.json`
- 固定官方文件推理：`.venv/Scripts/python.exe tools/verify_file_pipeline.py --model-root models --report artifacts/voice/file-pipeline.json`
- 翻译对照：`.venv/Scripts/python.exe tools/compare_translation_backends.py --model-root models --report artifacts/backend-ab/translation.json --warmup 1 --repeats 1`
- 识别对照：`.venv/Scripts/python.exe tools/compare_recognition_backends.py --model-root models --report artifacts/backend-ab/recognition.json --warmup 1 --repeats 1`
- 限时真实双路联调：`.venv/Scripts/python.exe tools/live_audio_check.py --model-root models --channel both --duration 30 --report artifacts/live-audio/manual.json`。该命令会开启麦克风与电脑声音；只在准备测试时运行。可通过 `--mic-device`、`--system-device` 指定设备，通过 `--play-sample ja` 播放固定官方样例。
- 可见窗口口述联调可加 `--manual-start`：先打开窗口，点击开始后才采音。`--expected-phrase` 只保存已知测试句的匹配分数，不保存正文；`--expect-silence mic` 可要求麦克风保持无字幕，用于检查噪声误触发。
- 语音版构建：`.venv/Scripts/python.exe tools/build.py --edition voice`
- 原型构建：`.venv/Scripts/python.exe tools/build.py --edition prototype`

构建隔离 DLL 搜索路径，拒绝覆盖已有输出，不打包用户配置或模型。冻结程序检查使用隔离的配置目录，不采音、不加载模型、不写设置。构建产物中的 `checks` 保存运行库报告、UI 报告和截图。

文件核验和真实联调命令均支持 `--recognition-backend`、`--translation-backend`、两组 `--*-device` 与 `--*-compute-type`，可直接核验所选组合。A/B 报告只使用预先编写的公开示例与固定官方 WAV，保存双方输出便于人工核对；计时通过不表示准确率更高。

## 当前验证边界

`0.4.8` 的同源比较对每个 ASR 后端保留全部 120 条结果（7 个自然区间、1 个诊断 EOS 区间、12 个旧提交区间，各六种处理候选）；重叠区间不当成独立句数。50% 原声保护恢复了部分弱人声，但空识别、观看感谢语和专名分歧仍在。native VAD 修正后的实际 DSP 重放无负长度警告，输出与同源离线 50% 混合逐样本一致；9 个在线段和 1 个诊断 EOS 段均重跑 Whisper＋Q8，空结果也保留。当前直播间实际为轮播，另行进行 60 秒可见窗口采集；同区间原声下也出现同样的观看感谢语和两段空识别。5/7 是提交候选的译文产出比例，不是准确率。不能用零运行错误、识别分数或两套 ASR 相似来替代原声准确性验收。单元测试为 1449 项及 74 项子检查通过；真实失败及提示回退原因见本轮报告。

`0.4.7` 纯 GTCRN 的旧基线为 8 条已显示译文 P50 1.473 秒、P95／最大 1.958 秒，另有 4/12 空识别；该计时不是 0.4.8 的新结果。[旧报告](artifacts/gtcrn-low-latency-20261017/validation.md)。

`0.4.6` 改为日译中段落对齐后只取当前句，并增加三类有源文依据的词义提示。初版段落方案在 12 条封存文本中出现“血量融化→失效”的退化，没有直接采用；随后术语修复及 `最初から` 误拦修复按已曝光回归验证，不宣称新盲测或整体准确率。真实直播又发现 `そうだろうな` 误拦，修复后按原顺序重放 13 条识别文本验证。最终全量为 1298 项测试、46 项子检查通过。当前直播仍出现 ASR 分歧、残句被补成确定含义和指代误补的问题；MDX 固定窗口也仍带来明显总延迟，不能用技术联调通过代替识别与翻译准确。完整样例、失败方案、独立语义审查、实际命令和直播边界见 `artifacts/q8-context-r3/validation.md`。

`0.4.5` 用错误窗口导出的原文重放真实 M2M100，复现两张截图的重复“想”和 U+2047 问号串。加入检查后，第一句可重试生成可读译文，第二句仍退化时明确失败并保留原文；正常句仍只生成一次。真实 Q8 对照发现，某些识别残句会触发同义改写式上文复述，有限检查仍有漏检。四种替代提示组织未同时通过词义与否定控制，没有替换现有生产提示；本轮文本对照不是直播识别准确率测试。详细记录见 `artifacts/translation-degeneration-20261017/`。
